Tutorial 02 • Integração para iniciantes

Use a API no seu próprio sistema.

Você não precisa usar o site Lumina. Qualquer interface capaz de enviar uma requisição HTTP pode pedir uma análise e exibir a resposta.

→
Ideia principalSeu botão envia dados; a API devolve JSON; seu JavaScript transforma esse JSON em interface.
Entender o fluxo
00

API sem mistério

Quatro palavras bastam para entender a comunicação.

1. EndereçoEx.: http://127.0.0.1:8000.
2. RotaEx.: /analise-texto.
3. RequisiçãoSeu JavaScript envia texto, perfil ou foto.
Resposta: a API devolve um texto estruturado em JSON. Em vez de mostrar o JSON cru, seu site lê campos como perfil.tipo_pele e recomendacoes para criar títulos, cartões e mensagens.
F

Frontend

É o que a pessoa vê. Contém botões, formulários e a variável com o endereço público da API. Não contém chave de IA.

B

Backend / API

Valida os dados, protege as chaves, chama o provedor de IA, consulta os produtos e monta a resposta.

01

Escolha onde a API vai rodar

O código do botão é quase igual. O que muda é o endereço.

Use enquanto desenvolve. Inicie o backend com uvicorn main:app --reload. O endereço será:

JavaScript
const API_URL = 'http://127.0.0.1:8000';

Somente aplicações no mesmo computador conseguem usar esse endereço. Se você enviar o seu HTML para outra pessoa, o navegador dela procurará a API no computador dela.

Use um domínio HTTPS do backend. A demonstração pública atual usa:

JavaScript
const API_URL = 'https://api-production-f6fd.up.railway.app';

Para um projeto real, substitua pelo endereço da sua própria hospedagem, banco e catálogo.

Um site HTTPS não deve chamar uma API HTTP. O navegador costuma bloquear essa mistura por segurança. Se o frontend está publicado com HTTPS, publique também a API com HTTPS.
02

Configure chaves sem expô-las

Seu frontend conhece o endereço da API; somente o backend conhece a chave do provedor.

Versão X: escolha um provedor

No arquivo .env do backend, defina AI_PROVIDER e preencha somente a chave escolhida. Os modelos abaixo são os padrões incluídos no projeto:

backend\.env
AI_PROVIDER=gemini
GEMINI_API_KEY=sua_chave_aqui
GEMINI_MODEL=gemini-3.5-flash-lite
backend\.env
AI_PROVIDER=openai
OPENAI_API_KEY=sua_chave_aqui
OPENAI_MODEL=gpt-5.6-luna
backend\.env
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sua_chave_aqui
ANTHROPIC_MODEL=claude-haiku-4-5-20251001

A v3.9.0 preservada utiliza a configuração Gemini. O suporte multiprovedor completo faz parte da Versão X. Em qualquer edição, o perfil manual e as recomendações já conhecidas funcionam sem chave; foto e texto dependem do provedor ativo.

Autorize o endereço do seu site

CORS é a lista de sites que podem chamar a API pelo navegador. Para o exemplo deste pacote, servido na porta 5500:

backend\.env
CORS_ORIGINS=http://localhost:5500

Em produção, use o domínio real, sem barra final:

backend\.env
CORS_ORIGINS=https://www.seusite.com.br
Não use * por comodidade em uma aplicação real. Autorize apenas as origens necessárias e reinicie o backend depois de alterar o .env.
03

Crie seu primeiro botão

Começaremos pelo perfil manual, porque ele testa a integração sem depender da IA.

1. O HTML cria a interface

index.html
<button id="recomendar">Ver recomendações</button>
<section id="resultado" aria-live="polite"></section>

<script src="app.js"></script>

2. O JavaScript envia o perfil

app.js
const API_URL = 'http://127.0.0.1:8000';

document.querySelector('#recomendar').addEventListener('click', async () => {
  const resposta = await fetch(`${API_URL}/recomendacoes`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      tipo_pele: 'oleosa',
      sensivel: true,
      tem_espinha: true
    })
  });

  const dados = await resposta.json();
  document.querySelector('#resultado').textContent =
    `Foram encontrados ${dados.total_recomendacoes} produtos.`;
});
P

POST

Indica que você está enviando dados para processamento. Não é o mesmo que simplesmente abrir um endereço.

J

JSON.stringify

Transforma o objeto JavaScript no formato de texto que a API espera no corpo da requisição.

Não pare no exemplo curto. Em produção, verifique resposta.ok, trate erros e desabilite o botão enquanto aguarda. O projeto funcional incluído neste pacote já demonstra essas proteções.

Use cada tipo de análise

Texto e perfil usam JSON. Foto usa FormData, próprio para arquivos.

Análise por texto

JavaScript
const resposta = await fetch(`${API_URL}/analise-texto`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    texto: 'Minha pele fica oleosa ao longo do dia e tenho espinhas frequentes.'
  })
});

const dados = await resposta.json();

Análise por foto

HTML + JavaScript
<input id="foto" type="file" accept="image/jpeg,image/png,image/webp">

const formulario = new FormData();
formulario.append('arquivo', document.querySelector('#foto').files[0]);
formulario.append('texto', 'Minha testa costuma ficar oleosa.'); // opcional

const resposta = await fetch(`${API_URL}/analise-foto`, {
  method: 'POST',
  body: formulario
});

const dados = await resposta.json();
Não defina manualmente o cabeçalho Content-Type ao enviar FormData. O navegador precisa criar sozinho o separador do arquivo. A foto deve ser JPG, PNG ou WEBP, até 5 MB.

A resposta pode ter estados diferentes

EstadoO que sua interface deve fazer
sucesso ou resposta com recomendaçõesMostrar perfil e produtos, agrupados por categoria.
informacoes_insuficientesPedir uma descrição melhor ou uma foto mais ampla.
fora_escopoExplicar que a ferramenta analisa apenas pele humana em contexto cosmético.
imagem_inadequadaMostrar a orientação recebida e manter a opção de escolher outra foto.
confirmacao_necessariaPedir ao usuário que confirme o tipo; depois chamar /recomendacoes, sem enviar a foto novamente.

Nunca apresente a análise como diagnóstico. Foto e texto são entradas opcionais e independentes; a experiência do seu frontend decide qual destacar.

06

Leve sua integração para a internet

Hospedar o frontend e hospedar a API são duas tarefas separadas.

1

Publique sua própria API

Envie o repositório para um serviço compatível com Python/FastAPI. O processo inicia normalmente com uvicorn main:app --host 0.0.0.0 --port %PORT% ou com o comando definido pelo provedor.

2

Crie variáveis no servidor

Cadastre AI_PROVIDER, a chave do provedor ativo, o modelo, APP_ENV=production, o caminho persistente do banco e CORS_ORIGINS. Não envie o seu .env

3

Use armazenamento persistente

O SQLite e as imagens não podem ficar apenas no disco temporário do deploy. Configure volume persistente; para tráfego maior, considere banco de servidor e armazenamento de objetos.

4

Aponte seu frontend

Troque API_URL pelo domínio HTTPS publicado. Em Vite, use VITE_API_URL; em HTML simples, altere a constante ou o campo de configuração do exemplo.

5

Teste como visitante

Abra em aba anônima e em outro celular. Teste /status, perfil manual, texto e foto. Observe o console do navegador e os logs do backend se algo falhar.

Rotas administrativas: na Versão X elas são ocultadas quando APP_ENV=production. Não as exponha simplesmente para colocar o painel na internet; primeiro implemente autenticação e autorização.

Diagnóstico rápido

Descubra se a falha está no navegador, na API ou no provedor de IA.

“Failed to fetch” ou “Não foi possível conectar”
Abra API_URL/status diretamente. Se não responder, a API está desligada ou o endereço está errado. Se responder, confira CORS, HTTPS e o console do navegador.
Erro de CORS no console
Inclua a origem exata do frontend em CORS_ORIGINS. Protocolo, domínio e porta fazem parte da origem: http://localhost:5500 é diferente de http://localhost:5173.
HTTP 422
O corpo não corresponde ao modelo esperado. Veja o campo detail da resposta. Texto exige ao menos 10 caracteres úteis; nomes de campos e tipos precisam estar corretos.
HTTP 413 ou 415 na fotografia
413 significa arquivo/dimensões acima do limite. 415 significa formato não aceito ou arquivo que não é realmente uma imagem. Use JPG, PNG ou WEBP até 5 MB.
HTTP 503 ou falha apenas nas rotas de IA
Perfil manual funcionar e texto/foto falharem costuma apontar para chave ausente, inválida, limite de quota, modelo ou instabilidade do provedor. Verifique os logs do backend.
A requisição responde, mas não há produtos
A integração está funcionando. Verifique o catálogo: produtos recomendáveis precisam estar ativos, com estoque maior que zero e compatíveis com o perfil.
Funciona localmente, mas não depois do deploy
Confirme que o frontend não continua apontando para 127.0.0.1, que a API usa HTTPS, que CORS contém o domínio publicado e que as variáveis foram definidas no serviço de hospedagem.
