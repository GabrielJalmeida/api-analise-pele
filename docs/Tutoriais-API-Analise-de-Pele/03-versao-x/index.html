Antes de instalar

Entenda a diferença entre o instalador pronto e o código-fonte.

EXE

Você recebeu *-setup.exe

Pode seguir diretamente para a instalação. Depois de instalado, o usuário final não precisa instalar Python, Node.js, Rust nem abrir o VS Code.

ZIP

Você recebeu apenas o código

Primeiro alguém precisa gerar o instalador em um computador Windows. A seção Gerar o instalador explica esse processo.

Não precisa de chave de IA para instalar nem para executar build_windows.bat. A chave é configurada depois, dentro do próprio painel, somente se você quiser usar análises ou importação por IA.
01

Instale o Skin Admin

O processo é semelhante a qualquer outro aplicativo do Windows.

1

Localize o instalador

O arquivo normalmente termina em -setup.exe. Dê dois cliques nele.

2

Leia o aviso do Windows

Esta edição não possui certificado comercial de assinatura. O SmartScreen pode exibir um aviso. Só prossiga se o instalador veio do repositório ou de uma pessoa em quem você confia. Nesse caso, use Mais informações → Executar assim mesmo.

3

Conclua a instalação

Siga o assistente do Windows. Ao terminar, procure Skin Admin no menu Iniciar e abra o aplicativo.

4

Aguarde a primeira inicialização

O aplicativo prepara uma API local e cria as pastas de dados. A primeira abertura pode demorar um pouco mais que as seguintes.

O banco começa vazio de propósito. A Versão X não mistura seus dados com os 50 produtos fictícios da demonstração Lumina.
02

Você pode começar pelo catálogo ou configurar a IA primeiro.

As seções principais do painel são:

SeçãoPara que serve

03

Monte seu catálogo

Cadastre poucos produtos manualmente ou importe muitos de uma vez.

Cadastro manual

Clique em Novo produto. Somente quatro informações são essenciais:

1

Nome

Como o produto será identificado.

2

Preço

Valor usado na apresentação e no registro demonstrativo.

3

Categoria

Limpeza, sérum, hidratante, protetor solar ou outros.

4

Tipo de pele

Oleosa, seca, mista, normal ou todos.

Marca, descrição, foto, conteúdo/volume e ativos principais são opcionais. Quando faltam, o frontend informa isso de forma neutra em vez de inventar dados.

Estoque começa em zero. O produto fica salvo, mas não entra nas recomendações até receber estoque maior que zero. Ele também precisa estar ativo e compatível com o perfil.

Importação em lote

Melhor para dados já organizados. O painel aceita até 1.000 produtos por arquivo CSV/XLSX de até 5 MB.

  1. Abra Importar catálogo.
  2. Escolha a opção de planilha e selecione o arquivo.
  3. Revise a prévia e corrija linhas sinalizadas.
  4. Confirme somente quando os dados estiverem certos.

Melhor para informações copiadas ou bagunçadas. Cole até 100 produtos por lote.

  1. Configure um provedor na seção IA.
  2. Cole o texto disponível.
  3. A IA organiza apenas as informações encontradas.
  4. Revise a prévia: preços, marcas ou ativos ausentes não devem ser inventados.
  5. Confirme o lote.
Nada é importado imediatamente. Os dois métodos geram uma prévia e exigem confirmação humana. Isso evita gravar dezenas de produtos com colunas trocadas.
04

Escolha a inteligência artificial

Você precisa configurar apenas um provedor; pode trocar quando desejar.

G

Gemini

Informe a chave Gemini e o modelo desejado. É o provedor originalmente usado pelo projeto.

O

OpenAI

Informe sua chave OpenAI e um modelo compatível configurado no aplicativo.

C

Claude

Escolha Anthropic/Claude, informe a chave e o modelo disponível na sua conta.

1

Abra “Configurar IA”

Selecione o provedor que você realmente pretende usar.

2

Informe modelo e chave

Copie a chave criada no portal do provedor. Não use uma chave recebida de terceiros.

3

Salve

A chave fica no diretório local do aplicativo e não é devolvida pela API. Feche a tela somente após a confirmação.

4

Faça um teste

Use uma descrição de pele clara ou a importação por texto. Se catálogo e perfil manual funcionam, mas IA não, confira chave, modelo, quota e internet.

Fotos são encaminhadas ao provedor escolhido. A aplicação não armazena a fotografia analisada, mas o uso deve ser informado ao usuário e seguir as políticas do provedor e as regras de privacidade aplicáveis.
05

Entenda o histórico

Ele demonstra uma seleção de rotina; não transforma o projeto em loja.

✓

O que é registrado

Nome, e-mail e itens somente após consentimento. O sistema guarda uma cópia do nome, marca, imagem e preço daquele momento.

×

O que não existe

Não há cobrança, cartão, frete, autenticação, nota fiscal ou checkout real. O estoque não diminui por padrão.

  • O histórico fica associado ao navegador por um identificador armazenado no banco apenas como hash.
  • O usuário pode apagar o próprio histórico.
  • Registros expiram automaticamente e têm retenção máxima de 365 dias.
  • A seção Pedidos no painel serve para visualizar os registros da API local.
Para vender de verdade, crie outro módulo. Pagamento, contas, segurança financeira, entrega, legislação e baixa de estoque precisam de projeto próprio.

O aplicativo não depende do banco da demonstração pública.

Backup simples

  1. Feche o Skin Admin.
  2. Pressione Win + R.
  3. Cole o caminho acima e pressione Enter.
  4. Copie a pasta inteira para um local seguro.

Ao restaurar, mantenha o aplicativo fechado e preserve a estrutura das pastas. Proteja o backup: config\.env pode conter uma chave privada.

Não publique essa pasta no GitHub. Ela pode conter catálogo real, histórico e chave de IA.

Se você só tem o código: gere o instalador

Esta parte é para quem vai preparar o arquivo de instalação, não para o usuário final.

Use um computador Windows com:

  • Python 3.12;
  • Node.js LTS;
  • Rust e Cargo;
  • Microsoft C++ Build Tools;
  • Microsoft Edge WebView2.

Extraia a Versão X, abra a pasta raiz e execute:

CMD • raiz da Versão X
build_windows.bat

O processo instala dependências, testa, compila a API auxiliar e monta o instalador. As saídas esperadas são:

Arquivos gerados
dist\lumina-api.exe
admin\src-tauri\target\release\bundle\nsis\*-setup.exe
Demora e usa bastante espaço. O script só precisa ser executado para criar uma nova distribuição. Não feche a janela durante a compilação.

Como alternativa, o repositório possui um fluxo manual chamado build-desktop-windows.yml, que pode gerar os artefatos em um executor Windows do GitHub.

Erros mais comuns

Primeiro identifique se a falha ocorre ao instalar, abrir, salvar produtos ou usar IA.

O Windows mostra “aplicativo não reconhecido”
O instalador não tem certificado comercial. Confirme a origem do arquivo antes de continuar. Se foi gerado por você ou veio do repositório confiável, abra Mais informações e escolha executar.
O painel abre, mas não carrega dados
Feche e abra novamente. Se persistir, consulte lumina-api.log na pasta de dados. Verifique também se outro programa está usando a porta local 8765.
O catálogo está vazio
Isso é esperado no primeiro uso. Cadastre um produto ou use a importação. Os produtos fictícios da Lumina não são adicionados automaticamente.
Cadastrei o produto, mas ele não é recomendado
Defina estoque maior que zero, mantenha o item ativo e confira o tipo de pele. Sem esses três requisitos, o produto fica no catálogo, mas não entra na curadoria.
Catálogo funciona, mas texto, foto ou importação com IA não
Essas funções exigem internet, provedor, modelo e chave válidos. Abra Configurar IA. Não é necessário preencher as chaves dos três provedores.
A importação encontrou erros
Revise a prévia. Quatro campos são essenciais: nome, preço, categoria e tipo de pele. Corrija nomes de categorias, números e produtos duplicados antes de confirmar.
O build_windows.bat falhou
Confirme Python 3.12, Node LTS, Rust/Cargo, C++ Build Tools e WebView2. Leia a primeira mensagem de erro real, não apenas a última linha. O arquivo docs\GUIA_DESKTOP.md do projeto detalha o build.
